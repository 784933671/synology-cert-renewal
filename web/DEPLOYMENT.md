# Docker 管理层部署验收

记录日期：2026-11-03，Asia/Shanghai。

## 已部署

- 设备：DS218+，DSM 7.3.1-86003 Update 1，Docker 24.0.2。
- 管理目录：`/usr/local/share/synology-cert-web`；容器：`synology-cert-web`。
- 管理入口：`https://ttxli.cn:18443`，IPv4 监听 `10.10.10.37:18443`，未监听 IPv6。
- 访问模式已按用户要求设为 `public`（允许外网）。登录后在“访问安全 → 访问模式”选择“仅内网 / 允许外网”，保存后自动应用。策略位于私有 `access/access.json`，原生监督进程与管理 API 共用同一份配置。

- 容器使用 UID/GID 10100、只读根文件系统、移除全部 capability、禁止提权，绑定逻辑 CPU 0，内存 384 MiB，非 root 用户进程数上限 96，每进程打开文件数上限 1024。该 DSM 内核不支持 CFS 配额及 PID cgroup，因此使用 cpuset 和 ulimits。

## 访问路径与验收边界

- 用户随后要求允许外网访问并提供可切换的配置。未改动路由器或腾讯云解析；“允许外网”解除来源限制，但不自动创建路由器映射。公网入口仍须能够到达 NAS 的 TCP 18443，DSM 原端口能访问不代表该端口一定可达。
- 切回“仅内网”会拒绝当前外网会话的后续请求。内网设备可将 `ttxli.cn` 解析到 `10.10.10.37` 后访问；无法进入页面时可在 NAS root 终端运行 `deployment.py set-access-mode --mode public` 恢复，不需要重置密码。
- 本次没有重做真实内网客户端浏览器验收。既有完整浏览器流程使用正式 HTTPS API 与隔离的桥接测试夹具；实际 NAS 的接口与防火墙验收单独记录。
- 本次验证了管理服务停止/启动，没有再次重启整台 NAS；下次实际重启或 DSM 升级后复查开机恢复。
- 本次没有强制申请、替换证书或重发通知邮件。首次签发、实际导入及邮件送达的既有结果见根目录 [脚本部署记录](../DEPLOYMENT.md)。
